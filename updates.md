# Обновления платформы — 2026-08-07

## 1. Оптимизация фронтенда (устранение лагов)

**Причина тормозов:** три анимированных размытых «blob»-пятна на фоне
(`filter: blur(70px)`, бесконечная CSS-анимация) находились *под* несколькими
элементами с `backdrop-filter: blur(...)` (шапка, каждая `.card`, `.stat-box`,
`.login-box`). Браузер вынужден был на каждом кадре заново пересчитывать
размытие фона под каждым из этих элементов одновременно — это тяжёлая
GPU/CPU операция, особенно на слабых устройствах и при скролле/большом числе
карточек на странице.

**Что изменено (`app/static/css/style.css`):**
- `backdrop-filter` убран из `.card`, `.stat-box`, `.login-box` — теперь у них
  просто полупрозрачный фон (`rgba(...)`) без блюра. Остался только в шапке
  сайта (`.site-header`), где он один и не пересчитывается под анимацией.
- Радиус размытия и размер фоновых пятен (`.aurora-blob`) уменьшены
  (70px → 45px, диаметр пятен ~15–20% меньше) — дешевле для отрисовки.
- Добавлен `contain: strict` на контейнер `.aurora`, чтобы браузер не
  пересчитывал layout/paint остальной страницы из-за анимации фона.
- Анимация фона теперь ставится на паузу, когда вкладка не активна
  (класс `.aurora.is-paused`, переключается через JS, см. ниже) — не грузит
  CPU в фоновой вкладке.

Внешний вид почти не изменился, но страницы стали заметно легче для рендера.

## 2. Новый файл `app/static/js/app.js`

Раньше на сайте вообще не было JavaScript. Добавлен один небольшой файл без
зависимостей, подключённый в `base.html`:

- **Пауза фоновой анимации** при уходе со вкладки (Page Visibility API) —
  часть оптимизации выше.
- **Автоскрытие флеш-сообщений** — уведомления об успехе/ошибке теперь сами
  исчезают через 6 секунд, плюс появилась кнопка «×» для ручного закрытия
  (стили `.flash-close` в CSS).
- **Клиентский поиск/фильтр** — универсальный механизм: элемент с
  `data-search-target="#id"` фильтрует все `[data-searchable]`-элементы
  внутри указанного контейнера по подстроке, без перезагрузки страницы.

## 3. Проверка домашних заданий преподавателем

Раньше ученик отправлял файл, но обратной связи от преподавателя в системе
не было никакой.

- В таблицу `submissions` добавлены поля `status`
  (`pending` / `approved` / `revise`) и `feedback` (текстовый комментарий).
- Новый маршрут `POST /admin/lessons/<id>/submissions/<id>/review` —
  преподаватель выставляет статус и комментарий к конкретной сдаче.
- На странице урока у преподавателя (`admin_lesson_detail.html`) под каждой
  сданной работой — форма с выбором статуса и полем для комментария.
- На странице урока у ученика (`student_lesson.html`) в истории отправок
  теперь виден статус («На проверке» / «Зачтено» / «На доработку») и текст
  комментария преподавателя.

## 4. Дедлайны уроков

- В таблицу `lessons` добавлено поле `due_date`.
- При создании и редактировании урока преподаватель может указать дату
  сдачи домашнего задания.
- Бейдж со сроком показывается на дашборде преподавателя, дашборде ученика
  и на странице урока; меняет цвет в зависимости от срока: обычный /
  жёлтый «скоро» (≤ 2 дней) / красный «просрочено» — логика в
  `app/__init__.py` (фильтр Jinja `due_status`).

## 5. Поиск и фильтрация по спискам

Без перезагрузки страницы, на чистом JS (см. п.2):
- Список уроков на дашборде преподавателя и ученика — поиск по названию.
- Список пользователей у преподавателя — поиск по имени и логину.
- Список учеников при настройке доступа к уроку — поиск по имени.

## 6. Миграция базы данных

Изменения схемы применяются автоматически и безопасно для уже существующей
базы (`instance/app.db`) — при запуске (`init_db_if_needed` в `app/db.py`)
новые столбцы добавляются через `ALTER TABLE`, только если их ещё нет.
Ничего вручную делать не нужно, старые данные не затрагиваются.

## Изменённые/добавленные файлы

- `app/db.py` — новые столбцы + безопасная миграция
- `app/__init__.py` — фильтр `due_status`
- `app/routes_admin.py` — `due_date` в создании/редактировании урока,
  маршрут `review_submission`
- `app/static/css/style.css` — оптимизация анимаций/блюра, новые стили
  (поиск, бейджи статуса/дедлайна, кнопка закрытия флеша)
- `app/static/js/app.js` — новый файл
- `app/templates/base.html` — подключение `app.js`
- `app/templates/admin_dashboard.html`, `student_dashboard.html` — поиск,
  бейдж дедлайна
- `app/templates/admin_lesson_new.html`, `admin_lesson_detail.html` — поле
  срока сдачи, форма проверки ДЗ, поиск учеников
- `app/templates/student_lesson.html` — бейдж дедлайна, статус/комментарий
  по сдаче
- `app/templates/admin_users.html` — поиск по пользователям

# Обновления платформы — 2026-08-07 (часть 2)

## 1. Хедер → сайдбар

Верхнее меню заменено на вертикальную панель слева (`app/templates/base.html`:
`.app-shell` / `.sidebar` / `.main-area`). Логотип, ссылки навигации и
пользователь с кнопкой «Выйти» теперь в сайдбаре; текущая страница
подсвечивается (`.sidebar-nav a.active`, определяется по `request.endpoint`).

На узких экранах (≤ 860px) сайдбар автоматически превращается в компактную
горизонтальную панель сверху (как раньше был header) — отдельного JS для
этого не нужно, только CSS.

## 2. Оценка домашних заданий баллом 0–10

- В `submissions` добавлено поле `score` (0–10, необязательное).
- Учитель ставит балл в той же форме проверки, где выбирает статус
  (`Зачтено` / `На проверке` / `На доработку`) и пишет комментарий —
  все три поля сохраняются одним действием (`admin.review_submission`).
- Балл валидируется на сервере (целое число 0–10), при ошибке форма не
  сохраняется и показывается сообщение.
- Балл виден ученику рядом со статусом (бейдж «N/10») на странице урока.

## 3. Общая статистика (баллы, графики)

Новая страница для каждой роли, доступна из сайдбара:

- **Ученик** → «Моя статистика» (`/dashboard/statistics`): средний балл,
  число доступных уроков, сколько работ сдано и сколько на проверке,
  столбчатый график баллов по урокам, полоса распределения статусов
  проверки.
- **Учитель** → «Статистика» (`/admin/statistics`): общее число уроков,
  учеников, сданных работ и средний балл по всему центру, график среднего
  балла по каждому уроку, распределение статусов проверки по всем работам.

Графики — без внешних библиотек: простые CSS-столбцы и CSS-полоса,
рендерятся через Jinja-макросы в `app/templates/_charts.html`
(`bar_chart`, `status_distribution`), стили — в конце `style.css`
(секция «Charts»).

## 4. Учитель → список студентов со статистикой

Новая страница «Студенты» (`/admin/students`, только у учителя): таблица
всех учеников с количеством доступных уроков, числом сданных работ,
разбивкой по статусам (зачтено / на проверке / на доработку) и средним
баллом по каждому. Есть поиск по имени/логину (тот же клиентский фильтр,
что и на других страницах).

## 5. Миграция базы данных

`submissions.score` добавляется автоматически через `_ensure_column` в
`app/db.py`, как и предыдущие поля — существующая база и данные не
затрагиваются.
